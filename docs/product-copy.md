# الگوی نگارش توضیحات و ویژگی‌های کلیدی محصول How to WP

این الگو برای نوشتن **توضیحات بلند** صفحهٔ محصول (محتوای ووکامرس در تب «توضیحات») و **ویژگی‌های کلیدی** (کارت‌های تب «امکانات فنی») است. متن را در `product.json` پر کنید، نه به‌صورت HTML آزاد در پیشخوان. لحن فارسی طبیعی باشد، با «ی» و «ک» فارسی. فقط چیزی را بنویسید که کد واقعاً انجام می‌دهد. قیمت، تخفیف و باشگاه را داخل این متن نگذارید.

مرجع اسکیما: [Howtowp/.github/schemas/product.schema.json](https://github.com/Howtowp/.github/blob/main/schemas/product.schema.json)

---

## صفحهٔ محصول واقعاً چه چیزی را نشان می‌دهد؟

بر اساس قالب `theme-howtowp` و صفحهٔ زندهٔ [ووسینک](https://howtowp.ir/product/woo-sync-plugin/):

1. **هero** عنوان فروشگاه، نسخه، و در صورت وجود **توضیح کوتاه** (`short_description` / excerpt) را نشان می‌دهد. توضیح کوتاه حداکثر حدود یک پاراگراف است (`max-width: 65ch`) و جای مقاله نیست.
2. **تب توضیحات** دو لایه دارد، به همین ترتیب:
   - اول کارت‌های **کاربرد و راه‌کار** از فیلد `use_cases` (جفت چالش / راه‌کار). عنوان کارت‌ها در قالب فعلاً «چالش ۱ / راه‌کار ۱» است و از روی متن ساخته نمی‌شود.
   - بعد مقالهٔ بلند داخل `<article class="htw-product-prose">`. این همان توضیحات ووکامرس است. قالب `h2` و `h3` و فهرست و لینک را خوب نشان می‌دهد. **داخل مقاله `h1` نگذارید**؛ صفحه از قبل یک عنوان اصلی دارد.
3. **تب امکانات فنی** یک گرید دو ستونه از کارت است: آیکن Material Symbol، عنوان کوتاه، و یک متن `text-sm` در حد یک تا دو جمله. منبع کارت‌ها فیلد `features` است، نه لیست گلوله‌ای داخل مقاله.
4. نسخه، سازگاری، تغییرات و قیمت از جای دیگری می‌آیند (هدر افزونه، Release، ووکامرس). آن‌ها را در توضیحات تکرار نکنید.

نسخهٔ زندهٔ توضیحات ووسینک طولانی است، چند بار ویژگی‌ها را تکرار می‌کند، از `h1` داخل مقاله استفاده کرده، و چند قابلیت را تبلیغ می‌کند که در کد نیست (مثل Migration و Dry Run). آن متن را الگو نکنید. این سند جایگزین آن است.

## لحن مشترک (فارسی و انگلیسی)

- فارسی محاورهٔ محترم و روان، نه شعار تبلیغاتی و نه نثر اداری خشک. انگلیسی معادل دقیق و حرفه‌ای باشد، نه ترجمهٔ تحت‌اللفظی.
- اغراق ممنوع: «قوی‌ترین»، «تنها»، «جادویی»، «لحظه‌ای» اگر صف یا درخواست شبکه در کار است، «رمزنگاری سرتاسری» اگر فقط امضای HMAC یا HTTPS دارید.
- ادعای صفحهٔ زنده را فقط وقتی نگه دارید که با سورس یکی باشد.
- عدد قیمت، تومان، درصد تخفیف، «رایگان با کلاب» و سیاست باشگاه را ننویسید. می‌توانید بگویید لایسنس به تعداد دامنه محدود نیست یا سورس با GPL در اختیار خریدار است.
- HTML داخل فیلدهای `product.json` نگذارید. پاراگراف‌ها را با خط خالی جدا کنید. howtowp-core بعداً HTML تمیز می‌سازد.
- نسخهٔ وردپرس و PHP را در مقاله تکرار نکنید؛ به تب سازگاری ارجاع بدهید.

## الف) توضیحات بلند — ساختار ثابت

متن را در آرایهٔ اختیاری `description_sections` بنویسید، با همین ترتیب و همین `id`ها. کل مقاله حدود **۴۰۰ تا ۷۰۰ کلمهٔ فارسی** (انگلیسی حدود ۳۵۰ تا ۶۰۰ کلمه) باشد. طولانی‌تر از این در تب، بعد از پنج کارت کاربرد، خسته‌کننده است.

هر بخش: هدف، سقف طول، و اسکلت خالی.

### 1. `opener` — قلاب و صورت‌مسئله

- **هدف:** خواننده در دو پاراگراف بفهمد مشکل چیست و این محصول همان را حل می‌کند.
- **طول:** ۱ تا ۲ پاراگراف، حدود ۸۰ تا ۱۴۰ کلمه. **بدون heading** (مقاله با `h1` شروع نشود).
- **نکنید:** تکرار عنوان فروشگاه، وعدهٔ قیمت، فهرست ویژگی‌ها.

```text
id: opener
heading: (نگذارید)
body.fa: [پاراگراف ۱: موقعیت دردناک و ملموس]
[خط خالی]
[پاراگراف ۲: محصول چه می‌کند و چه چیزی را تضمین نمی‌کند]
body.en: [همان معنا]
```

### 2. `audience` — مخاطب

- **هدف:** هم کاربر عادی (مدیر فروشگاه، آژانس) و هم وایب‌کدر را جدا و صادقانه خطاب کنید.
- **طول:** یک جمله مقدمه + ۴ تا ۷ گلوله، هر گلوله یک جمله.
- **heading نمونه:** «این افزونه برای چه کسانی است؟» / "Who is this for?"

```text
id: audience
heading.fa / heading.en:
body.fa / body.en: [یک جمله مقدمه]
items: [
  { fa, en },  // کاربر عادی
  { fa, en },
  { fa, en },  // در صورت وجود: وایب‌کدر / توسعه‌دهنده
]
```

### 3. `how_it_works` — روش کار در ۳ گام

- **هدف:** نصب تا اولین نتیجه، بدون جزئیات توسعه‌دهنده.
- **طول:** یک جمله مقدمه + **دقیقاً ۳ گام**، هر گام ۱ تا ۲ جمله. فیلد `steps` اجباری است.
- **heading نمونه:** «چطور کار می‌کند؟» / "How it works"
- **نکنید:** چهار گام یا بیشتر، وعدهٔ همگام‌سازی لحظه‌ای اگر کار با صف انجام می‌شود.

```text
id: how_it_works
heading.fa / heading.en:
body.fa / body.en: [مقدمهٔ کوتاه]
steps: [
  { fa, en },  // نصب / پیش‌نیاز
  { fa, en },  // اتصال یا تنظیم اصلی
  { fa, en },  // استفادهٔ روزمره
]
```

### 4. `key_features` — ویژگی‌های کلیدی (در مقاله)

- **هدف:** فقط یک مقدمهٔ کوتاه. خود کارت‌ها از آرایهٔ `features` در تب امکانات می‌آیند. اینجا لیست ۱۲ موردی تکرار نکنید.
- **طول:** ۱ تا ۲ جمله. اگر لازم است، یک خلاصهٔ یک‌خطی از تم ویژگی‌ها کافی است.
- **heading نمونه:** «ویژگی‌های کلیدی» / "Key features"

```text
id: key_features
heading.fa / heading.en:
body.fa / body.en: [مقدمه + ارجاع به تب امکانات فنی]
```

### 5. `use_cases` — کاربردها (در مقاله)

- **هدف:** یک تصویر کلی از موقعیت استفاده. کارت‌های چالش / راه‌کار بالاتر در همین تب از `use_cases` ساخته می‌شوند؛ متن آن کارت‌ها را اینجا رونویسی نکنید.
- **طول:** ۱ تا ۲ پاراگراف کوتاه.
- **heading نمونه:** «در چه موقعیت‌هایی به کار می‌آید؟» / "When it helps"

```text
id: use_cases
heading.fa / heading.en:
body.fa / body.en: [روایت کوتاه، بدون تکرار پنج کارت]
```

### 6. `why_howtowp` — چرا How to WP؟

- **هدف:** تمایز فروشنده، نه تکرار قابلیت فنی. محورها: سورس باز با GPL، بدون قفل دامنه یا هزینهٔ جدا برای هر نصب، قابل‌گسترش با `AI-GUIDE.md`.
- **طول:** یک جمله مقدمه + ۳ تا ۵ گلوله.
- **نکنید:** رقم قیمت، مقایسهٔ توهین‌آمیز با رقبا، «رایگان با کلاب».

```text
id: why_howtowp
heading.fa / heading.en:
body.fa / body.en: [مقدمه]
items: [
  { fa, en },  // GPL / سورس در اختیار خریدار
  { fa, en },  // بدون محدودیت تعداد دامنه / تمدید اجباری جدا
  { fa, en },  // قابل‌گسترش با AI-GUIDE و hookها
]
```

### 7. `requirements` — پیش‌نیاز و سازگاری

- **هدف:** فقط نکات اضافه نسبت به هدر و `readme.txt`.
- **طول:** یک جمله ارجاع به تب سازگاری + ۳ تا ۵ گلوله.
- **نکنید:** «Requires at least» و «Tested up to» را اینجا عدد ندهید؛ آن‌ها همگام می‌شوند.

```text
id: requirements
heading.fa / heading.en:
body.fa / body.en: [ارجاع به تب سازگاری]
items: [ { fa, en }, ... ]
```

### 8. `cta` — دعوت به اقدام

- **هدف:** قدم بعدی روشن: دمو، دانلود از حساب، یا شروع از منوی افزونه.
- **طول:** ۱ تا ۲ جمله. اگر `demo_url` دارید، همان URL را بنویسید.
- **نکنید:** قیمت و شمارش معکوس.

```text
id: cta
heading.fa / heading.en:
body.fa / body.en: [دعوت کوتاه + لینک دمو در صورت وجود]
```

## ب) ویژگی‌های کلیدی — فرمول کارت‌ها

کارت‌ها در تب «امکانات فنی» با `features[]` پر می‌شوند. **۶ تا ۹ کارت**. کمتر از ۶ تب را خالی نشان می‌دهد (مثل سه کارت ضعیف فعلی ووسینک روی سایت). بیشتر از ۹ در گرید دو ستونه شلوغ است.

### فرمول هر کارت

| قسمت | قاعده |
| --- | --- |
| `id` | kebab-case پایدار. بعد از انتشار عوضش نکنید. |
| `title` | ۲ تا ۵ کلمه. **با فایده شروع شود**، نه با نام فنی قطعه. |
| `description` | ۱ تا ۲ جمله: اول چه می‌کند، بعد چرا برای خریدار مهم است. برای کارت `text-sm` کوتاه بماند. |
| `icon` | نام Material Symbol مثل `sync`، `tune`، `security`. مسیر فایل نگذارید. |
| ترتیب | از باارزش‌ترین فایده برای خریدار به جزئی‌تر. معمولاً: ایدهٔ اصلی محصول، کنترل، جلوگیری از خسارت، بعد امکانات جانبی. |

### بکن / نکن

**عنوان**

- نکن: «متای سئو» (اسم قابلیت، فایده ندارد)
- بکن: «حفظ تنظیمات سئو»
- نکن: «سینک همتابه‌همتا، یک‌طرفه یا دوطرفه» (طولانی و فنی)
- بکن: «همگام‌سازی بدون واسطه»
- نکن: «ابزار Migration دستی» اگر در کد اجرا نمی‌شود

**توضیح**

- نکن: سه جملهٔ فنی با نام الگوریتم و جزئیات ذخیره‌سازی کلید
- بکن: دو جملهٔ روشن دربارهٔ رفتار و نتیجه برای کاربر
- نکن: «ارتباط کاملاً رمزنگاری‌شده» وقتی فقط درخواست‌ها امضا می‌شوند
- بکن: «درخواست‌ها امضا می‌شوند و مستقیم بین سایت‌ها می‌روند؛ HTTPS توصیه می‌شود»

## قواعد نسخهٔ انگلیسی

همان هشت بخش و همان `id`ها. `body.en` باید هم‌معنی `body.fa` باشد، نه خلاصهٔ فقیرتر و نه متنی کاملاً جدا.

- لحن: واضح و حرفه‌ای، بدون hype («game-changer»، «blazing-fast»، «enterprise-grade» بی‌مدرک).
- عنوان کارت: ۲ تا ۵ کلمه، benefit-first (مثال: "You decide conflicts" بهتر از "Manual conflict resolution UI").
- توضیح کارت: ۱ تا ۲ جمله، what + why.
- املای محصول (WooSync، How to WP) یکدست باشد.
- اگر اصطلاحی در فارسی رایج است و در انگلیسی مبهم است، در انگلیسی همان رفتار را توصیف کنید نه آوانگاری را.

## نمونهٔ کارشده: ووسینک

متن زیر از `description_sections` ریپوی `howtowp/woo-sync` (برنچ `dev`) آمده و با کد افزونه هم‌خوان است. قابلیت‌هایی که صفحهٔ زنده تبلیغ می‌کرد و در کد اجرا نمی‌شوند (Migration، Dry Run، پشتیبانی کامل ACF به‌عنوان قابلیت درجه یک، رمزنگاری سرتاسری payload) عمداً نیامده‌اند.

اگر چند فروشگاه ووکامرس دارید و محصول مشترک بین‌شان زیاد است، هر تغییر کوچک به چند ورود جدا و چند ویرایش تکراری تبدیل می‌شود. یک قیمت جاافتاده یا یک عکس فراموش‌شده کافی است تا مشتری دو رقم مختلف ببیند.

ووسینک همین کار را از روی دوش شما برمی‌دارد. محصولات، نوشته‌ها، دسته‌بندی‌ها و تصاویر را بین چند سایت وردپرسی همگام می‌کند؛ یک‌طرفه یا دوطرفه. شما تعیین می‌کنید چه فیلدی سفر کند و اگر دو طرف هم‌زمان یک مورد را عوض کنند، هیچ داده‌ای بدون تأیید شما بازنویسی نمی‌شود.

## این افزونه برای چه کسانی است؟

ووسینک هم برای مدیر فروشگاه نوشته شده و هم برای کسی که می‌خواهد رفتار سینک را با کد گسترش بدهد.

- صاحب چند فروشگاه ووکامرس با کاتالوگ مشترک که نمی‌خواهد هر تغییر را چند بار وارد کند.
- کسب‌وکاری که هم مارکت‌پلیس دارد و هم فروشگاه تخصصی، یا فروشگاه فیزیکی را به فروش آنلاین وصل کرده است.
- آژانسی که برای چند مشتری فروشگاه می‌سازد و باید محتوا را بین محیط‌ها جابه‌جا کند.
- وایب‌کدر یا توسعه‌دهنده‌ای که می‌خواهد با فیلترهای ووسینک، بدون ویرایش هسته، نوع پست یا قاعدهٔ سفارشی اضافه کند.

## چطور کار می‌کند؟

راه‌اندازی در سه گام انجام می‌شود. بعد از اتصال، سینک خودکار روی ذخیره است و کارها در صف Action Scheduler می‌روند؛ نه به‌صورت جادویی لحظه‌ای روی یک سرور خارجی.

1. ووسینک را روی هر سایت شرکت‌کننده نصب و فعال کنید. ووکامرس باید روی همان سایت‌ها فعال باشد.
2. از منوی ووسینک، آدرس سایت مقابل و کلید API را وارد کنید تا اتصال (handshake) برقرار شود. هر دو طرف باید افزونه را داشته باشند.
3. جهت سینک و فیلدهای مجاز را انتخاب کنید. از آن به بعد، ذخیرهٔ یک محصول یا نوشته کار را در صف می‌گذارد و به سایت متصل می‌فرستد.

## ویژگی‌های کلیدی

کارت‌های کامل این بخش در تب امکانات فنی همان صفحه آمده‌اند. خلاصه‌اش این است: سینک همتابه‌همتا با کنترل فیلد، رفع تعارض دستی، انتقال هوشمند تصویر، محصولات متغیر، متای سئو، و ارتباط امضاشده بین خود سایت‌ها.

## در چه موقعیت‌هایی به کار می‌آید؟

جفت‌های چالش و راه‌کار را بالاتر در همین تب می‌بینید. به‌طور خلاصه، ووسینک جایی به کار می‌آید که چند فروشگاه باید کاتالوگ مشترک را هم‌راستا نگه دارند، بدون اینکه قیمت یا موجودی هر فروشگاه لزوماً یکی باشد، و بدون اینکه ویرایش هم‌زمان یکی از نسخه‌ها را خاموش پاک کند.

## چرا How to WP؟

خرید از How to WP یعنی افزونه مال شماست و می‌توانید رویش کار کنید، نه اینکه به یک لایسنس دامنه یا سرویس بسته گره بخورید.

- کد با مجوز GPL-2.0-or-later در اختیار شماست و می‌توانید آن را برای پروژه‌های خود شخصی‌سازی کنید.
- استفاده به تعداد مشخصی دامنه یا نصب محدود نمی‌شود و برای خود افزونه تمدید اجباری جداگانه‌ای تعریف نشده است.
- فایل AI-GUIDE.md همراه محصول است تا وایب‌کدرها بتوانند با Cursor یا Claude، از روی hookهای واقعی و بدون ویرایش هسته، افزونه را گسترش بدهند.

## پیش‌نیازها

حداقل نسخهٔ وردپرس و PHP از هدر افزونه و پروندهٔ readme می‌آید و در تب سازگاری همان صفحه به‌روز می‌شود. علاوه بر آن:

- ووکامرس باید روی هر سایت شرکت‌کننده نصب و فعال باشد؛ صف کارها از Action Scheduler ووکامرس استفاده می‌کند.
- ووسینک را روی همهٔ سایت‌های متصل نصب کنید. معماری همتابه‌همتاست و به سرویس ابری واسطه نیاز ندارد.
- برای انتقال درخواست‌های امضاشده بین سایت‌ها HTTPS قویاً توصیه می‌شود.
- برگه (page) به‌صورت پیش‌فرض سینک نمی‌شود؛ نوع پست سفارشی را می‌توان با یک افزونهٔ همراه و hookهای مستند اضافه کرد.

## از همین‌جا شروع کنید

اگر می‌خواهید قبل از تهیه، محیط را ببینید، پیش‌نمایش زنده در https://howtowp.ir/demos/woosync/ در دسترس است. پس از تهیه، فایل نصب را از حساب خود در howtowp.ir دانلود کنید، روی سایت‌ها فعال کنید و از منوی ووسینک اتصال را بسازید. راهنمای گسترش برای وایب‌کدرها داخل خود افزونه، در پروندهٔ AI-GUIDE.md است.

دو نمونهٔ قبل و بعد از اعمال فرمول:

**`peer-to-peer-sync`**
- قبل: عنوان «سینک همتابه‌همتا، یک‌طرفه یا دوطرفه» — طولانی و فنی. توضیح سه جمله بود.
- بعد: عنوان «همگام‌سازی بدون واسطه». توضیح: سایت‌ها مستقیم با هم حرف می‌زنند و به سرور مرکزی نیاز ندارند. برای هر اتصال می‌توانید جهت را روی ارسال، دریافت، هر دو یا توقف بگذارید.

**`seo-meta`**
- قبل: عنوان «متای سئو» — اسم قابلیت، نه فایده. توضیح: با روشن بودن فیلد seo_meta، تنظیمات Yoast SEO، Rank Math و SEOPress همراه محصول یا نوشته منتقل می‌شوند. پیشوند کلیدها از قبل در لیست مجاز تنظیمات هست.
- بعد: عنوان «حفظ تنظیمات سئو». توضیح: با روشن بودن فیلد seo_meta، مقادیر Yoast، Rank Math و SEOPress همراه نوشته یا محصول منتقل می‌شوند تا صفحهٔ مقصد اسنیپت و دادهٔ سئو را از دست ندهد.
